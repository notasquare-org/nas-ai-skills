## 型（どの案件でもこの順）

| # | 場面 | 中身 | 長さの目安 |
|---|---|---|---|
| 1 | タイトル | 帯「〈先方名〉様向け 検証版（PoC）のご紹介」、価値をひとことで（例:「紙の書類を、すぐ使えるデータに」）、アプリ名、株式会社Not a Square・年月 | 5〜7秒 |
| 2 | いまの課題 | 先方の今の作業を3段階ほどで（例: 紙で受け取る → 手で入力し直す → 時間がかかる）。最後に「この〜を短くすることが目的です」 | 8〜12秒 |
| 3 | 解決のしかた | PoCの画面を、使う順に1場面1つずつ（選ぶ → 設定 → 実行 → 結果）。ここが中心 | 全体の半分 |
| 4 | 到達点 | 確かめたこと（✓）と、まだのこと（△）。数字は測ったものだけで、条件を小さく添える | 8〜12秒 |
| 5 | 次の一歩 | 先方に頼みたいこと（例:「御社の実際のデータで、試させてください」「まずは小さく、現場で試すところから」） | 5〜7秒 |
| 6 | 終わり | 「ご覧いただき、ありがとうございました」。声・BGM付きの版ではクレジットも出す | 3〜4秒 |

全体で1.5〜2分。1920×1080、30fps。コンセプトを伝える段階（PoCがまだ粗い）なら、3を「使う人の流れ」と「安心して使える理由」に分けてもよい。

## 文の書き方
- 先方の言葉で書く。業界の言葉は使ってよいが、技術の言葉は言い換える。
- 1文を短く。字幕は1行20〜25字ほど、2行まで。
- 読み上げる文では、英字をカタカナにする（PDF→ピーディーエフ、CSV→シーエスブイ など）。読み間違えやすい漢字は、ひらがなにする（描き直し→かき直し）。字幕は英字・漢字のままでよい。
- 確かめていないことを、できたように言わない。到達点の場面で「これからです」と言う。
- 他社の素材を映す場面では、画面の端に出典を出す。
- 台本（場面・画面・ナレーション／字幕）を、動画のフォルダの `台本.md` か README に表で残す。

## 2本作る

| 版 | 用途 | 中身 |
|---|---|---|
| 声・BGM付き | 先方に送って見てもらう | ナレーション（VOICEVOX）、BGM、字幕または画面の文字、最後にクレジット |
| 音なし | 打ち合わせで、ユーザーが話しながら流す | 声もBGMもない。画面の文字（と字幕）だけで流れが分かるように |

## 声とBGM
- 声は VOICEVOX の冥鳴ひまり（スタイルID 14、速さ1.05）を既定にする。商用・法人の利用ができ、申請は要らない。クレジット「VOICEVOX:冥鳴ひまり」の表記が必要。
- macOSの読み上げ音声（say、Kyoko など）は使わない。Appleの規約で個人的・非商用の利用に限られ、商用の場での録音・公開が禁じられている。一度これで作ってしまい、作り直したことがある。
- ほかの声を使うときは、エンジンから利用規約を読んでから（voicevox.md）。
- BGMは `scripts/bgm.py` で合成したオリジナルにする。音源素材を使わないので、権利の心配がない。声が出ている間はBGMを下げる（両方式のスクリプトで処理済み）。
- クレジットの文:「ナレーション：VOICEVOX:冥鳴ひまり ｜ BGM：オリジナル（Not a Square 制作）」
- 音量は、ナレーションを −16 LUFS、BGMを −27 LUFS 前後にそろえる（スクリプトで処理済み）。

## 作り方を選ぶ

| | A. HTMLアニメ方式 | B. スライド＋字幕方式 |
|---|---|---|
| 向いている | 流れや考え方（コンセプト）を、動きで見せたい。図やイラストが多い | PoCの実際の画面を、操作の順に見せたい |
| 中身 | HTMLで場面を作り、Chromeで1コマずつ描いて動画にする。声が長い場面は、表示し終えた所で止めて待つ | 説明画面とPoCの画面写真を並べ、白へのフェードでつなぎ、字幕を焼き込む |
| 直す所 | `video.html` の文字と `data-in` / `data-out`（秒）、`narration.json` | `scenes.json` の文と画像 |
| 必要なもの | Node.js、pnpm、Google Chrome、ffmpeg、uv、VOICEVOX | Python 3、ffmpeg（libass付き）、uv、VOICEVOX。説明画面を作るのに A の道具も使う |

どちらにするかは案件ごとに決める。迷ったら、理由を1行添えて案を出し、ユーザーに選んでもらう。

## A. HTMLアニメ方式の手順

1. `scripts/html-video/` の中身と `scripts/bgm.py` を、案件の `video/` にコピーする。
2. `video/` で `pnpm install` を実行する（playwright-core が入る。ブラウザは手元の Google Chrome を使う）。
3. `video.html` の〈 〉を案件の内容に書き換える。
   - 各要素の `data-in` は出る秒、`data-out` は消える秒。
   - `data-fx` は動き方で、up / scale / left / right / fade のどれか。
   - `data-active-in` / `data-active-out` を付けると、その間だけ濃く表示される（説明中の手順の強調）。
   - PoCの画面写真は `assets/` に置く。
   - 時間で動くCSSアニメーション（animation、transition）は使わない。1コマずつ `renderAt(秒)` で描くので、見た目は秒数だけで決まるようにする。
   - 動画の長さは、`DURATION` を書き換える。
4. `pnpm stills` で、確認用の静止画を `out/stills/` に出し、自分で開いて1枚ずつ見る（文字のはみ出し、重なり、誤字）。出す秒は `video.html` の `STILLS`。
5. 音なし版: `pnpm render` → `out/video.mp4`
6. 声・BGM付き版:
   - `narration.json` の `duration` を `DURATION` と同じにする。`lines` に、場面ごとの文を書く。
     - `at`: 話し始める場面の秒
     - `hold`: その場面の表示が出そろう秒
   - VOICEVOX を起動してから、`uv run --with numpy --with scipy python build_voiced.py --speaker 14 --name 冥鳴ひまり` → `out/video-voice.mp4`
   - 声が場面より長いときは、`hold` の所で映像を止めて待つ（アニメの速さは変えない）。
7. 出来上がりを、案件と内容が分かる名前にコピーする（references/delivery.md の名前の付け方）。

## B. スライド＋字幕方式の手順

1. `scripts/slide-video/` の中身と `scripts/bgm.py` を、案件の `video/` にコピーする。
2. 説明画面を作る（タイトル・いまの課題・到達点・次の一歩・終わり）。
   - 手順Aと同じく `scripts/html-video/` を別のフォルダにコピーし、`video.html` を説明画面だけに書き換える。
   - `node render.mjs --stills --times 3,10,…` で静止画にし、`assets/` に置く（例: `slide_title.png`）。
3. PoCの画面写真を `assets/` に置く。連番の静止画は、`wipe_%03d.jpg` のような名前にする。
4. `scenes.json` に、名前・出典・場面を書く。場面ごとに書くのは次のとおり。
   - `image` または `sequence`: 画像
   - `speech`: 読み上げる文
   - `captions`: 字幕（`\N` で改行）
   - `credit`: 出典を出す位置（top / bottom）
   - `caption_top`: 画面の下に大事なものがある場面では、字幕を上に出す
5. VOICEVOX を起動してから `python3 make_video.py` を実行する。`out/` に「〈名前〉（声・BGM付き）.mp4」と「〈名前〉（音なし）.mp4」ができる。

## 書き出したら確かめる
- **長さ**: `ffprobe -v error -show_entries format=duration -of csv=p=0 <動画>`。2分前後に収まっているか。
- **音**:
  - 声・BGM付きの版に音声があり、音量がそろっているか。`ffmpeg -i <動画> -af ebur128=framelog=quiet -f null -` の I が −16 前後になっていればよい。
  - 音なし版に、音声の流れが入っていないか。
- **画**: 各場面とクレジットの静止画を取り出して開く。文字のはみ出し・誤字・出典・クレジットの表示を確かめる。静止画は `ffmpeg -ss <秒> -i <動画> -frames:v 1 x.png` で取り出せる。
- **中身**: 数字が FEASIBILITY.md と合っているか。未確認のことを「これから」と言っているか。
