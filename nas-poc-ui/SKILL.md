# NaS PoC UI — Liquid Blue

NaSの商談用Web PoCで、信頼感と技術力を伝える。PCとスマホを同じ重みで扱う。
対話で選んだ「リキッド・ブルー」と、改善した入力欄・フォームを共通基準にする。方向性と以下の禁止事項はユーザーの決定であり、CSSの数値は再現用の初期値として扱う。

## 画面見本

該当する画面を作成・調整するときに、対応する見本を確認する。

- [PCのAIチャット・入力欄](assets/reference-chat-desktop.png)
- [PCの登録フォーム](assets/reference-form-desktop.png)
- [スマホの登録フォーム](assets/reference-form-mobile.png)

見本の営業ワークスペースや企業名は題材。実際のPoCの業務内容に置き換え、見本のメニュー項目や文言まで固定してコピーしない。

## ブランドと不要な装飾

- 淡い青を基調に、落ち着いた文字色と明確な操作で信頼感を作る。強い青は主操作と選択状態に絞る。
- PoCにはNaSのロゴを入れない。ロゴの代わりのマークも自動で作らない。
- **「営」のような文字を丸に入れた、根拠のないユーザーアバターを作らない。** 画面の空きを埋めるために、架空のプロフィール、イニシャル、アカウントメニューを足さない。
- ユーザー・アカウント操作が実際の要件にある場合は、その操作に必要な表示を設計する。装飾目的のアバターとは区別する。
- ナビゲーションや操作を説明する機能アイコンは使える。既存のアイコンセットを統一して使い、主要操作には文字ラベルを付ける。

## ガラスとレイアウト

- Appleのアプリ画面とLiquid Glassの考え方を参考にする。製品紹介ページの大きなヒーローや宣伝用の構成にはしない。
- ガラスはツールバー、サイドバー、下部ナビなどの操作層に集める。本文、チャット回答、一覧、フォーム全体を透かさない。
- 背後の淡い青がわずかに透け、ぼかしと細い光の縁で浮いて見える質感にする。強い発光、大きな影、過剰なガラスの重なりは避ける。
- 本文を大きな角丸カードで何重にも囲わない。余白、文字の階層、必要な区切りで整理する。
- 丸みは残しつつ引き締める。ガラス面14px、ボタン10px、入力欄8pxを初期値にし、すべてをカプセル形にはしない。
- 背景が単調なときは、操作部の背後に控えめな青の色面を置くことはできる。全画面に装飾を増やすためのものではない。
- Webのぼかし・透明度・ハイライトで近づける表現であり、AppleのネイティブLiquid Glassそのものと説明しない。

## 実装への組み込み

配色と素材を実装するときは [assets/tokens.css](assets/tokens.css) を読む。既存のフレームワーク、コンポーネント、テーマの仕組みに合わせて取り込む。新しいUIライブラリを前提にしない。

- スタイルをアプリのルートにスコープし、既存画面の全体スタイルを上書きしない。
- ガラス表現がなくても操作できる、不透明な代替面を用意する。透明度低減の設定と動きの低減設定を尊重する。
- テーマは既存アプリの設定を引き継ぐ。ライト・ダークの両方がある場合は、それぞれで文字と入力欄を読める状態にする。
- PCでは文字付きサイドバー、スマホでは下部ナビを基本候補にする。620pxを初期の切り替え目安とし、内容が収まるかで調整する。
- 一覧は狭い幅で行を縦に組み直す。PC画面をそのまま縮小して文字や操作対象を小さくしない。
- フォームの編集文字は16px程度、タップ対象は44px程度を目安にする。必須情報をホバーだけに隠さない。

## 画面ごとの適用

### AIチャット

- 会話本文を主役にし、回答を装飾カードで分断しない。回答の見出しと段落で情報を整理する。
- 案件などの参照対象をコンパクトに示す。根拠データがある場合は、参照元を開いて確認できるようにする。
- 入力は一行分の高さから始め、文章量に合わせて広げる。大きな空の入力カードを常時置かない。入力面の右に送信ボタンを置き、参照情報などの補足は面の外に小さくまとめる。
- メッセージのラベルを残し、送信は文字で示す。入力文字は16px程度、送信の操作対象は44px以上を初期値にする。空入力では送れず、送信後は入力欄を初期の高さへ戻す。
- 送信・処理中・応答・失敗の状態を、実際に接続している機能に合わせる。サンプル応答を本物のAI生成と誤認させない。

### 顧客・案件管理

- 顧客名、案件名、進行状況、次のアクションを優先する。見せる業務に必要な項目だけを並べる。
- 案件登録など、その画面の主操作を分かりやすく置く。画面を埋めるための集計カードを増やさない。
- スマホでは顧客・案件のまとまりを保って縦に並べる。状態は色だけでなくラベルで示す。

### 入力画面

- ラベルと必須・任意を入力前後とも見える位置に残す。顧客名・案件名・ステータスなどの短い基本項目は、一つの静かな塗りの面にまとめ、項目間を細い線で区切る形を基本にする。項目ごとに大きな枠を繰り返さない。
- 短いラベルは入力の左に置ける。狭い幅や長いラベルでは上下へ組み直し、編集する文字の幅を確保する。長文のメモは別の複数行入力に分ける。
- 入力中は淡い青と控えめな境界色で対象を示す。ガラスは入力欄そのものに重ねず、文字の読みやすい面を使う。既存のキーボードフォーカス表示を消さない。
- 必須項目のエラーは対象の近くに短く表示し、`aria-invalid` と説明の関連付けを使う。修正中も入力内容を保持し、保存後は結果が分かる表示にする。
- 保存を青の主操作、キャンセルを控えめな文字操作として区別し、実際の保存先と挙動に合わせる。

## 商談デモとして確認すること

- 架空のデータを使う場合は、サンプルだと分かる表示にする。表示するボタンはデモの範囲で意味のある反応を持たせる。
- PC幅とスマホ幅で表示し、ナビ、チャット入力、案件登録の主要経路を実際に操作する。
- 320px程度の狭い幅でも、意図しない横スクロールや切れたボタンがないか確認する。
- 不要なロゴ、文字アバター、プロフィールの飾りを追加していないか確認する。
